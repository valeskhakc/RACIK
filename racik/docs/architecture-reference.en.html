Racik architecture

An AKG-grounded, cost-constrained menu planner for Indonesia's Makan Bergizi Gratis program. 18,133 regional recipes become costed, nutrition-bearing dishes; an integer programme selects the menu; SEA-LION handles the language. It ships in Indonesian and English from one codebase. This is the map of how that works, and where it is weak.

01System

Racik has one architectural commitment, and everything else follows from it: the deterministic engine owns every number, and the language model owns none of them.

An SPPG operator writes ordinary Indonesian. SEA-LION reads the intent and decides which tools to call. Those tools run a CP-SAT optimiser over a corpus of dishes whose nutrition came from TKPI 2020 and whose cost came from a priced ingredient table. The answer is assembled from tool output, and every response carries the trace of calls that produced it.

The grounding rule

No gram, rupiah, calorie or adequacy figure is ever produced by the model. Each one is computed by the engine and handed to the model as tool output. An LLM that quietly rounded a protein figure would destroy the single property that makes Racik worth using, so it is never given the chance to compute one.

02Request paths

Two entry points reach the same engine. The form path is direct and deterministic; the language path adds SEA-LION in front of it. Neither can produce a number the other could not.

Form path — POST /api/plan

PlanBody → PlanRequest → MenuOptimizer.solve()
  ├── _candidates()   pre-filter per slot: exclusions, cost ceiling,
  │                   component-only slots, dedupe by name, rank, top 220
  ├── CP-SAT model    tray composition · variety · soft nutrient floors
  │                   · energy ceiling · fat ≤30% energy · soft budget
  └── _extract()      → PlanResult(days, relaxations, budget_overrun)
                      → _serialise() → compliance rows + notes

Language path — POST /api/ask

question → RacikOrchestrator.ask()
  ├── client not configured? → rule-based parse_intent() → plan_menu → text
  └── agent loop (≤6 steps, repeated-call detection)
        SEA-LION → tool_calls → _invoke() → tool result JSON
                 ↺ fed back as role:"tool" messages
        → final prose + ToolInvocation trace + plan payload

Failure in the language path degrades rather than breaks: a missing API key, a network error, or an HTTP error from SEA-LION all fall back to the rule-based planner, which returns the same numbers from the same tools.

03Build pipeline

scripts/build_db.py runs this once, in about 30 seconds, and writes data/racik.db. These steps are numbered because they are genuinely ordered — each consumes the previous one's output.

1

Parse household measures

racik/urt.py — 260,734 ingredient lines to grams by explicit rule. "2 ons ikan" → 200 g, "1 papan tempe" → 200 g, "secukupnya garam" → 2 g flagged as unquantified. 99.98% resolved.

2

Match to composition

racik/tkpi.py — token-set matching onto TKPI codes via 200+ curated aliases, documented proxies, then fuzzy fallback. Never substring: "ayam" is inside "Bayam".

3

Compute nutrition

racik/nutrition.py — edible g = gross × BDD/100, then per-100 g composition, then FAO/INFOODS retention factors for the inferred cooking method. Frying oil counted at 10% absorption.

4

Cost on gross weight

racik/prices.py — cost is charged on as-purchased weight, not edible weight, through a fallback ladder: TKPI code → ingredient name → food group → table default. The basis used is reported.

5

Classify and scale

Assign the Isi Piringku tray slot from ingredient mass shares, estimate servings from the slot-defining mass against the reference portion, then divide the whole pot by that count.

6

Persist

Write foods, dishes and dish_lines to SQLite with indexes on slot, province, island and main food, plus the 22 served components (rice, tubers, fruit, milk) at several portion sizes.

07Orchestrator

SEA-LION v4.5 (AI Singapore, May 2026) is the language layer. It was chosen for two documented properties: it is trained on Southeast Asian languages, so operators write ordinary Indonesian, and it is tuned for precise function-calling and agentic tool-use.

Loop safety

  • Hard step cap — MAX_STEPS = 6, enforced by the loop, not requested in the prompt.
  • Repeated-call detection — an identical call signature more than MAX_REPEATED_CALLS = 2 times is short-circuited with an instruction to use the result already held.
  • Total trace — unknown tools, bad arguments and blocked repeats all land in the trace. Two bugs were caught here in testing: both were error paths that returned early and skipped the trace, which would have hidden exactly the events worth seeing.
  • Graceful degradation — no key, or any SeaLionError, routes to parse_intent() driving the same tools.

7bCandidate rubric

"Why was this dish never considered?" is the question an SPPG nutritionist actually asks, so the pre-filter states its rules rather than burying them in a loop. POST /api/candidates returns the gates, the weights, and how many dishes each gate removed.

GateRule
G1 slotmust fill the tray slot being filled
G2 sourcestaple and buah accept served components only
G3 exclusionsterm matched against dish name and full ingredient index
G4 dish idexplicit operator veto
G5 cost ceilingcost per portion ≤ 85% of the ingredient budget
 
value      = min(protein/target, 1.5) + min(energy/target, 1.5)
efficiency = value / (cost/budget + 0.15)
score      = efficiency + 3.0 x regional_fit + 2.0 x data_quality
What the funnel exposes. For SD in Central Java the cost ceiling alone removes 9,084 of 13,525 animal-protein dishes — two thirds of the corpus priced out before the solver runs. That is the budget story, measured rather than asserted.

7cThe report, and translation

POST /api/report is the deliverable: one printable page carrying the menu, per-day AKG compliance, every relaxed floor, the aggregated shopping list in gross kilograms, methodology caveats and signature blocks. Self-contained HTML with print styles, bilingual, with advisory micronutrients tagged INFO in every table.

POST /api/translate glosses dish names with SEA-LION, batched 40 at a time against the 10 req/min limit and cached. The gloss sits beside the Indonesian name, never replaces it, and reports whether it came from the model or the offline glosser.

10Test suite

python -m pytest tests -q — 137 tests, about 90 seconds. No network and no API key required.

Engine — tests/test_racik.py (48)

  • Number and unit parsing: fractions, mixed numbers, ranges, vulgar glyphs, malformed input that must degrade rather than crash a 260k-line build.
  • The ons = 100 g convention and spoon anchors (1 sdm = 10 ml, 1 sdt = ⅓ sdm).
  • The ayam/bayam substring trap, inverted TKPI names, identity-modifier guards, and an integrity check that every alias code exists.
  • BDD purchase weights, vitamin A as retinol equivalents, price fallback basis reporting.
  • Frying-oil absorption, including the boundary where the cap begins to bite.
  • Soft-floor behaviour under a deliberately impossible budget: a menu must still come back, with the shortfall named.

Orchestration — tests/test_orchestrator.py (28)

  • The agent loop is driven by a scripted stand-in for SEA-LION, so no key or network is needed.
  • Tool results are fed back to the model; the step cap holds against a model that only ever calls tools; repeated calls are short-circuited.
  • Unknown tools and bad arguments are reported in the trace, never raised.
  • Intent parsing, including that unreadable input yields defaults rather than a guess.
  • Fallback still returns real numbers, and exclusions actually reach the planner.

11Known limits

Read this section before quoting any number from Racik externally.

  • Micronutrients are not enforced. Secondary sources disagree on AKG 2019 iron and zinc — boys 10–12 are reported as both 8 and 13 mg. Ca, Fe, Zn, vitamin A and vitamin C are computed and displayed, marked INFO, and excluded from constraints until transcribed from the Permenkes 28/2019 original. This is the single highest-value open task.
  • Servings are estimated. The corpus states no yield, so servings come from slot-defining ingredient mass against the reference portion. This is the largest source of per-portion error.
  • Retention factors are approximations, applied at category level by inferred cooking method — FAO/INFOODS says as much of its own tables.
  • Prices are a dated snapshot. The daily Bapanas and BI endpoints are undocumented and geo-restricted; live refresh is best-effort and falls back.
  • The corpus is home cooking, so quantities and costs skew household rather than wholesale SPPG procurement.
  • Region assignment is inherited from the source workbook's keyword classifier (11,715 high / 6,418 medium confidence).
  • The live SEA-LION path is unverified against the real API. Transport, auth, throttling and tool-call parsing follow the documented contract and the loop is fully tested against a stand-in, but no call has been made with a real key. Set SEALION_API_KEY and check /api/orchestrator reports mode: sealion.

12Bilingual builds

Racik ships in Indonesian and English from one codebase. Two hand-maintained forks would drift within a week, so the two release builds differ only in which language they default to.

Both archives carry the complete ID/EN catalogue and the in-app toggle, so either build can run in either language. Dish names are never translated — "Tempe Mendoan" is the name of the food, not a label.

Where language lives

LayerMechanism
racik/i18n.py Prose the server writes itself: methodology notes, the rule-based fallback answer, and the one unit that differs (kkal / kcal)
API responses Labels already travel bilingually — every compliance row and relaxation carries label_id and label_en, so the client picks
ui/index.html A STRINGS catalogue with t(), data-i18n attributes, locale-aware number formatting, and a toggle persisted to localStorage
Orchestrator A language directive appended to the system prompt, so the interface language wins when the question itself is ambiguous

Producing the archives

python scripts/package.py     # -> dist/racik-id.zip, dist/racik-en.zip

The script rewrites exactly two marked lines per build — DEFAULT_LANG in ui/index.html and in racik/i18n.py — swaps in the matching README, and refuses to write an archive that fails its structural checks. Everything else is byte-identical between the two.

racik.db is deliberately excluded. It is a 66 MB derived artefact that scripts/build_db.py regenerates in ~30 seconds from the raw sources that are included. Shipping it would quadruple the archive for something the recipient can rebuild — and a stale copy is worse than none. Each archive is 6.5 MB, 29 files.

Guarded by tests

  • Both catalogues must hold identical key sets, non-empty values, and matching {placeholders}.
  • No key may be identical across languages — that catches a block copy-pasted and never translated.
  • Every t("…") call and data-i18n attribute in the UI must resolve to a defined key, and the runtime-composed families (slot.*, n.*) must be complete.
  • The DEFAULT_LANG build marker must be present and well-formed, or packaging fails loudly.

Both archives were verified by extracting them to a clean directory, building the database from the packaged raw sources, and running the full suite: 102 passed in each. That run caught a real defect — a test asserting on Indonesian output that failed in the English build.

13Runbook

export SEALION_API_KEY=...                   # optional; enables the orchestrator
python -m uvicorn racik.api:app --port 8000  # http://127.0.0.1:8000
python -m pytest tests -q                    # 102 tests
python scripts/package.py                    # dist/racik-id.zip + racik-en.zip

Dependencies: ortools, fastapi, uvicorn, rapidfuzz, pandas, openpyxl, pytest. The SEA-LION client is stdlib only.
